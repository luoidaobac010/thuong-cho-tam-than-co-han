🔢 KÝ HIỆU TIỆM CẬN — Big-O, Ω, Θ

💡 Bản chất — "Hàm này lớn cỡ nào khi n → ∞?"

Ký hiệu tiệm cận dùng để so sánh tốc độ tăng của các hàm. Không quan tâm hằng số, chỉ quan tâm dạng tăng.

📋 3 Ký Hiệu Chính

Ký hiệuTênÝ nghĩaĐịnh nghĩa chính thức
$O(g(n))$ Big-O (cận trên) $f(n)$ tăng chậm hơn hoặc bằng $g(n)$ $\exists c > 0, n_0 > 0$: $f(n) \le c \cdot g(n)$, $\forall n \ge n_0$
$\Omega(g(n))$ Big-Omega (cận dưới) $f(n)$ tăng nhanh hơn hoặc bằng $g(n)$ $\exists c > 0, n_0 > 0$: $f(n) \ge c \cdot g(n)$, $\forall n \ge n_0$
$\Theta(g(n))$ Big-Theta (cận chặt) $f(n)$ tăng cùng tốc độ với $g(n)$ $\exists c_1, c_2, n_0 > 0$: $c_1 g(n) \le f(n) \le c_2 g(n)$
💡
Mẹo nhớ: O = "tối đa bằng" (≤) | Ω = "tối thiểu bằng" (≥) | Θ = "đúng bằng" (=). Nếu vừa $O$ vừa $\Omega$ → thì là $\Theta$.

📝 Cách CM bằng định nghĩa (dạng hay thi)

Ví dụ: CM $3n^2 + 5n = O(n^2)$

Cần tìm: $c > 0$ và $n_0 > 0$ sao cho $3n^2 + 5n \le c \cdot n^2$, $\forall n \ge n_0$.

Lời giải: $3n^2 + 5n \le 3n^2 + 5n^2 = 8n^2$ (vì $n \le n^2$ khi $n \ge 1$)

Chọn $c = 8$, $n_0 = 1$ → $3n^2 + 5n \le 8n^2$, $\forall n \ge 1$. ∎

// Khung CM chuẩn (ghi vào bài thi):
1. Ghi: "Cần tìm c > 0, n₀ > 0 sao cho f(n) ≤ c·g(n), ∀n ≥ n₀"
2. Biến đổi: thay hạng nhỏ bằng hạng lớn nhất (n ≤ n², log n ≤ n, ...)
3. Thu gọn: f(n) ≤ (tổng hệ số) · g(n)
4. Kết luận: "Chọn c = ..., n₀ = ... → QED ∎"

📊 Thứ tự hàm phổ biến (nhỏ → lớn)

$O(1)$→ $O(\log n)$→ $O(n)$→ $O(n\log n)$→ $O(n^2)$→ $O(n^3)$→ $O(2^n)$→ $O(n!)$
📌
Mẹo phân lớp: Bỏ hệ số + bỏ hạng nhỏ. VD: $5n^2 + 3n\log n + 7$ → $O(n^2)$.

📋 Dạng 2: Lập phương trình đệ quy

4 bước lập PT
  1. Base case: Khi nào dừng? → $T(1) = O(1)$
  2. Phần đệ quy: Gọi lại bao nhiêu lần? Kích thước con bao nhiêu?
  3. Phần không đệ quy: Ngoài lời gọi đệ quy, còn làm gì? → $f(n)$
  4. Viết PT: $T(n) = (\text{số lần gọi}) \times T(\text{kích thước con}) + f(n)$

📋 Dạng 3: Giải PT đệ quy — Master Theorem

Master Theorem — $T(n) = aT(n/b) + f(n)$

So sánh $f(n)$ với $n^{\log_b a}$:

CaseĐiều kiệnKết luậnVí dụ
1 $f(n)$ nhỏ hơn $n^{\log_b a}$ $T(n) = \Theta(n^{\log_b a})$ $8T(n/2)+n^2$: $\log_2 8=3>2$ → $\Theta(n^3)$
2 $f(n)$ bằng $n^{\log_b a}$ $T(n) = \Theta(n^{\log_b a} \log n)$ $2T(n/2)+n$: $\log_2 2=1=1$ → $\Theta(n\log n)$
3 $f(n)$ lớn hơn $n^{\log_b a}$ $T(n) = \Theta(f(n))$ $2T(n/2)+n^2$: $\log_2 2=1<2$ → $\Theta(n^2)$
// Cách dùng Master Theorem (3 bước):
1. Xác định: a = ?, b = ?, f(n) = ?
2. Tính: $n^{\log_b a}$ = ?
3. So sánh f(n) với $n^{\log_b a}$:
  nhỏ hơn → Case 1 → $\Theta(n^{\log_b a})$
  bằng    → Case 2 → $\Theta(n^{\log_b a} \cdot \log n)$
  lớn hơn → Case 3 → $\Theta(f(n))$

🔧 Khung mã giả theo từng mô hình

Mã giả — Chia để trị
function SOLVE_DC(A, left, right):
  if left == right: return base_case
  mid = (left + right) / 2
  L = SOLVE_DC(A, left, mid)
  R = SOLVE_DC(A, mid+1, right)
  return COMBINE(L, R)

ĐPT: $T(n) = 2T(n/2) + f_{\text{combine}}(n)$ → Master Theorem.

Mã giả — Tham lam
function SOLVE_GREEDY(candidates):
  S ← ∅
  SORT(candidates theo tiêu_chí)
  for each x in candidates:
    if IS_FEASIBLE(S ∪ {x}): S ← S ∪ {x}
  return S

ĐPT: Thường $O(n \log n)$ (sắp xếp chi phối).

Mã giả — Quy hoạch động
function SOLVE_DP(input):
  T ← bảng [0..n][0..m], fill 0
  T[0][*] = ..., T[*][0] = ... // cơ sở
  for i = 1 to n:
    for j = 1 to m:
      T[i][j] = FORMULA(...)
  return T[n][m]

ĐPT: Thường $O(n \times m)$ hoặc $O(n \times W)$ = kích thước bảng.

📙 PHẦN 1: CHIA ĐỂ TRỊ (Divide and Conquer) — Buổi 4

💡 Bản chất — "Chia nhỏ, trị riêng, gộp lại"

Chia bài toán lớn thành các bài toán con nhỏ hơn cùng dạng, giải đệ quy từng bài con, rồi kết hợp kết quả lại thành lời giải cho bài toán ban đầu.

🔧 Khung 3 Bước Chuẩn

DIVIDE: Chia nhỏ→ CONQUER: Giải đệ quy→ COMBINE: Gộp kết quả
function DIVIDE_AND_CONQUER(problem):
  if problem đủ nhỏ (base case):
    return giải trực tiếp
  // DIVIDE
  subproblems ← chia problem thành các bài con
  // CONQUER
  for each sub in subproblems:
    results[sub] ← DIVIDE_AND_CONQUER(sub)
  // COMBINE
  return COMBINE(results)
📐 Công thức đệ quy tổng quát (Master Theorem)

$$T(n) = aT(n/b) + f(n)$$

Trong đó: $a$ = số bài con, $b$ = tỉ lệ chia, $f(n)$ = chi phí chia + gộp.

  • Merge Sort: $T(n) = 2T(n/2) + O(n)$ → $O(n \log n)$
  • Quick Sort (TB): $T(n) = 2T(n/2) + O(n)$ → $O(n \log n)$ (worst: $O(n^2)$)
  • Binary Search: $T(n) = T(n/2) + O(1)$ → $O(\log n)$
💡
Phân biệt với QHĐ: Chia để trị các bài con KHÔNG gối nhau (mỗi bài con độc lập). Nếu bài con trùng lặp → chuyển sang QHĐ.

📘 PHẦN 2: QUY HOẠCH ĐỘNG (Dynamic Programming) — Buổi 5

💡 Bản chất QHĐ — "Tính 1 lần, xài n lần"

Giống đệ quy nhưng lưu kết quả các bài toán con vào bảng để không tính lại. Thay vì gọi đệ quy lặp, ta tra bảng lấy kết quả ngay.

🔑 Hai Đặc Trưng Bắt Buộc

1. Cấu trúc con tối ưu (Optimal Substructure)

Lời giải tối ưu của bài toán lớn chứa lời giải tối ưu của bài toán con.

Cách lập luận "Cắt-Dán": Giả sử lời giải con không tối ưu → thay bằng cái tốt hơn → bài toán cha tốt hơn → mâu thuẫn với giả thiết cha đã tối ưu. ∎

2. Bài toán con trùng lặp (Overlapping Subproblems)

Vẽ cây đệ quy sẽ thấy cùng một bài con bị gọi nhiều lần. QHĐ giải mỗi bài con đúng 1 lần rồi lưu vào bảng.

📋 Quy Trình 6 Bước Giải Bài QHĐ

B1: Chọn bảng→ B2: Ô lưu gì?→ B3: Cơ sở & PTQHĐ→ B4: Điền bảng→ B5: Đáp án→ B6: Truy vết
⛔
Lưu ý chết người khi điền bảng:
Với bảng tam giác trên (LCS, Nhân ma trận), các ô $i > j$ (nửa dưới đường chéo) phải để trống. Điền số hay dấu X vào đó = mất điểm cả bảng!
💡
Mẹo "Ô lưu gì?": Luôn là một con số tính được (giá trị lớn nhất, độ dài, số phép nhân tối thiểu...). Không bao giờ lưu "vị trí" hay "cả dãy con".

📝 Ví Dụ 1: Dãy Con Chung Dài Nhất (LCS)

Đề bài

Cho $X = \langle A, B, C, B \rangle$ (độ dài $m=4$) và $Y = \langle B, A, C, B \rangle$ (độ dài $n=4$).

Tìm dãy con chung dài nhất của $X$ và $Y$.

Bước 1–2: Chọn bảng & Ô lưu gì?

Bảng 2 chiều $M[0..m][0..n]$ kích thước $(m+1) \times (n+1) = 5 \times 5$.

Ô $M[i][j]$ lưu: Độ dài LCS của $X[1..i]$ và $Y[1..j]$.

Bước 3: Cơ sở & Phương trình QHĐ

Cơ sở: $M[i][0] = 0$ và $M[0][j] = 0$ (so sánh với dãy rỗng → LCS = 0).

Phương trình:

$$M[i][j] = \begin{cases} M[i-1][j-1] + 1 & \text{nếu } X[i] = Y[j] \\ \max(M[i-1][j], \; M[i][j-1]) & \text{nếu } X[i] \ne Y[j] \end{cases}$$
Bước 4: Điền bảng (từ trái sang, trên xuống)
MBACB
00000
A 0 0 1 ↖ 1 1
B 0 1 ↖ 1 1 2 ↖
C 0 1 1 2 ↖ 2
B 0 1 ↖ 1 2 3 ↖

Quá trình tính ô [4][4]: $X[4]=B = Y[4]=B$ → $M[3][3]+1 = 2+1 = $ 3

🧭 Cách điền từng ô bảng LCS — Giải thích dễ hiểu

📌 Trước hết: mỗi ô lưu gì?

Ô M[i][j] trả lời câu hỏi: "Nếu mình chỉ xét $i$ chữ đầu của X và $j$ chữ đầu của Y, thì chúng giống nhau được tối đa bao nhiêu chữ?"

Ví dụ: M[2][4] = "Xét X chỉ có A,B và Y đầy đủ B,A,C,B → chung được mấy chữ?" → 2 chữ (A và B).

🔵 Hàng 0 và Cột 0: luôn = 0

Đây là trường hợp "chưa có chữ nào" → so dãy rỗng với bất kỳ ai → chung = 0. Điền 0 ngay, không cần nghĩ.

🟡 Các ô còn lại: chỉ cần hỏi 1 câu

Nhìn chữ ở hàng (X[i]) và chữ ở cột (Y[j]), hỏi: "2 chữ này có giống nhau không?"

// Đang ở ô M[i][j], nhìn X[i] và Y[j]:

if X[i] == Y[j]:   // 2 chữ GIỐNG nhau
  → Lấy ô CHÉO ↖ + 1
  → Tô VÀNG, ghi mũi tên ↖
  → "Bắt cặp thành công! Tăng thêm 1"

else:              // 2 chữ KHÁC nhau
  → Lấy MAX(ô TRÊN ↑, ô TRÁI ←)
  → Để TRẮNG, không mũi tên
  → "Không match, giữ kết quả tốt nhất cũ"

$$M[i][j] = \min_{i \le k < j} \big\{ M[i][k] + M[k+1][j] + d_{i-1} \cdot d_k \cdot d_j \big\}$$

function GREEDY(candidates):
  S ← ∅     // Tập lời giải
  SORT(candidates theo tiêu chí chọn)  // Bước quan trọng!
  for each x in candidates:
    if IS_FEASIBLE(S ∪ {x}):  // x thỏa ràng buộc?
      S ← S ∪ {x}
  return S

📝 Ví Dụ 2: DFS — Duyệt theo chiều sâu

Đề bài

Cùng đồ thị trên, duyệt DFS từ đỉnh A (dùng đệ quy).

Quá trình DFS từ A (đệ quy)
  DFS(A) → thăm A
   ├─ DFS(B) → thăm B
   │   ├─ DFS(D) → thăm D
   │   │   └─ (hàng xóm B đã thăm → quay lui)
   │   └─ DFS(E) → thăm E
   │       └─ DFS(F) → thăm F
   │           └─ (hàng xóm C chưa thăm)
   │               └─ DFS(C) → thăm C
   │                   └─ (hàng xóm A,F đã thăm → quay lui)
   └─ (C đã thăm → quay lui → DONE)

✅ Thứ tự duyệt DFS: A → B → D → E → F → C

📌
Mẹo nhớ: BFS = Bảng (Queue, tầng lớp) | DFS = Di sâu (Stack/đệ quy, đào hang). Cùng đồ thị nhưng thứ tự duyệt khác nhau!

🎯 Tại sao phần này quan trọng?

Khi đọc đề, bạn cần trả lời 2 câu hỏi theo thứ tự:

  1. Dùng thuật toán gì? → Nhìn từ khóa trong đề.
  2. Kẻ khung / bảng ra sao? → Mỗi thuật toán có một "khuôn" trình bày riêng.

Sai bước 1 → cả bài sai. Đúng bước 1 nhưng sai bước 2 → mất điểm trình bày.

📙 1. Dấu Hiệu → Chia Để Trị

🔎 Từ khóa trong đề

  • "Chia đôi" / "chia thành 2 nửa"
  • "Tìm Min-Max bằng phương pháp chia để trị"
  • "Merge" / "Partition"
  • Đề yêu cầu viết công thức đệ quy $T(n)$
📝 Cách điền khung — Khung 3 bước chuẩn

Bài làm bắt buộc phải thể hiện đủ 3 phần:

PhầnNội dung cần điềnHình thức trình bày
DIVIDE Vẽ cây chia nhỏ bài toán, mỗi nhánh là một bài con Sơ đồ cây phân cấp (vẽ bằng ký tự / \ hoặc mũi tên). Chia đến khi chạm base case (1 phần tử)
CONQUER Ghi kết quả trả về từ mỗi base case Ghi ngay bên cạnh lá cây. Ví dụ: [3] → (min=3, max=3)
COMBINE Gộp kết quả từ dưới lên, ghi rõ phép gộp Kẻ bảng theo từng mức: Mức | Gộp gì + gì | Kết quả. Hoặc ghi trực tiếp trên cây
💡

B2 Ô lưu gì? Ghi rõ ý nghĩa của mỗi ô. Ví dụ: "$M[i][j]$ = độ dài LCS của $X[1..i]$ và $Y[1..j]$". Luôn là một con số tính được, KHÔNG bao giờ lưu "vị trí" hay "dãy con"

3 LỖI CHẾT NGƯỜI khi điền bảng QHĐ:
1. Điền số vào nửa dưới đường chéo (bảng tam giác) → mất điểm cả bảng!
2. Chỉ ghi số cuối mà không ghi quá trình tính (ví dụ: $k=1$: 36, $k=2$: 40, min = 36) → bị trừ điểm trình bày.
3. Nhầm ô đáp án: LCS lấy ở $M[m][n]$ (dưới phải) nhưng Nhân ma trận lấy ở $M[1][n]$ (trên phải) — nhầm là mất!

📝 Cách điền khung — Theo từng thuật toán

🔹 BFS — Bảng mô phỏng Queue

Kẻ bảng với các cột:

Bước | Dequeue (lấy ra) | Hàng xóm chưa thăm | Enqueue (đưa vào) | Trạng thái Queue | Đã thăm

Bắt đầu: Enqueue đỉnh nguồn. Kết thúc: Queue rỗng. Ghi rõ thứ tự duyệt cuối cùng.

🔹 DFS — Sơ đồ đệ quy dạng cây

Vẽ cây đệ quy bằng ký tự ├─ └─:

DFS(A) → thăm A
  ├─ DFS(B) → thăm B
  │   └─ DFS(D) → thăm D
  │       └─ (quay lui)
  └─ ...

Ghi rõ khi nào "quay lui" (hàng xóm đã thăm hết). Kết luận thứ tự duyệt.

🔹 Dijkstra — Bảng cập nhật khoảng cách

Kẻ bảng với các cột:

Bước | Chọn đỉnh (d nhỏ nhất) | d[v₁] | d[v₂] | ... | Cập nhật gì?

Khởi tạo: $d[\text{nguồn}]=0$, tất cả còn lại $= \infty$. Mỗi bước: chọn đỉnh chưa xét có $d[\ ]$ nhỏ nhất, cập nhật hàng xóm bằng d[u] + w(u,v). Đánh dấu đỉnh đã fix bằng tô đậm.

🔹 Kruskal — Bảng xét cạnh

Kẻ bảng với các cột:

Lượt | Cạnh | Trọng số | Tạo chu trình? | Quyết định | Các thành phần liên thông

Sắp tất cả cạnh tăng dần trước. Xét lần lượt. Dừng khi chọn đủ $V-1$ cạnh.

🔹 Prim — Bảng mở rộng cây

Kẻ bảng với các cột:

Bước | Tập cây hiện tại | Cạnh nhẹ nhất nối ra ngoài | Chọn cạnh | Thêm đỉnh

Bắt đầu từ 1 đỉnh. Mỗi bước: chọn cạnh nhẹ nhất nối từ cây đến đỉnh ngoài cây. Dừng khi tất cả đỉnh đã vào cây.

⚠️
Lỗi hay gặp với đồ thị:
1. BFS quên đánh dấu "đã thăm" khi Enqueue → duyệt trùng đỉnh → sai.
2. Dijkstra dùng cho cạnh âm → kết quả sai (phải dùng Bellman-Ford).
3. Kruskal quên kiểm tra chu trình → kết quả không phải cây.
4. Không ghi thứ tự duyệt ở cuối bài BFS/DFS → thiếu kết luận.
